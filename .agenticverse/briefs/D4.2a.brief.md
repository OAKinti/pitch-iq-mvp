## Steps
1. `fakeRealtime.ts`: `createFakeRealtimeServer()` holding member rows and result rows for one group, plus `connect()` returning a fake `SupabaseClient` and a per-client control handle. The fake client supports exactly what `SupabaseRepository` uses: `from(t).select(c).eq(...)` (thenable), `channel(name).on(...).subscribe(cb)`, `removeChannel`. Controls needed by the tests:
   - `deferQueries(client)` / `resolveNext(client)` / `resolveAllReversed(client)` / `rejectNext(client)` so fetches can settle out of order.
   - `emit(client, payload?)`, `emitTwice`, and delivery of a list of events in a chosen order per client.
   - `status(client, 'SUBSCRIBED' | 'CHANNEL_ERROR' | 'TIMED_OUT' | 'CLOSED')`.
   - `rowOrder(client, 'asc' | 'desc' | 'shuffled')` for CON-7.
   - server mutations: `addResult(userId, ovr, submittedAt)`, `addMember`, `removeMember`.
   - `truth()`: the expected `GroupMemberStat[]` in ascending `userId` order.
2. `repository.ts`:
   - `listGroupMembers`: sort the mapped array by `userId` ascending with a plain `<` / `>` compare (no `localeCompare`).
   - `subscribeToGroup`: one private `refresh()` used by both the change handler and the SUBSCRIBED status. `const n = ++started; fetch.then(m => { if (closed || n <= delivered) return; delivered = n; onChange(m); }).catch(() => undefined)`. The change handler takes no argument (SEC-12). Keep D2.3a's closed flag and single `removeChannel`.
3. `GroupSessionScreen.tsx`: a ref flag set when the subscription callback first fires; the initial `listGroupMembers().then` applies its result only while the flag is unset.
4. `groupSync.test.ts`: two `SupabaseRepository` instances on two fake clients of one server, one test per acceptance name. Compare each client's last `onChange` argument with `truth()` using `toEqual`. For the ranking check, apply the screen's sort (`[...m].sort((a, b) => b.bestOvr - a.bestOvr)`) inside the test.
5. `groupSync.test.tsx`: render `GroupSessionScreen` through `renderNavigator` with a fake `repository` prop whose `listGroupMembers` is a deferred promise and whose `subscribeToGroup` captures the callback. Fire the callback, then resolve the stale list, and assert the leaderboard still shows the snapshot.

## Notes
- State-based convergence is the design: never apply event payloads as deltas.
- A `CLOSED` status or a rejected fetch must not throw and must not call `onChange`.
- Flush promises with `await Promise.resolve()` loops or `await new Promise(r => setTimeout(r, 0))`; no real delays above 0 ms.
- `@testing-library/react-native` 14: `render`, `fireEvent.*`, `act` are async - always `await`.
- Known limit to state in the report, not to fix: the Realtime publication contains only `group_session_results` (migration 001, frozen), so roster joins and leaves reach a client at its next trigger. The tests model this by emitting an event after `addMember` / `removeMember`.
